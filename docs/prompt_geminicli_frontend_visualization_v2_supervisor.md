# GeminiCli Prompt（Supervisor版）：监管级可视化与可解释性强化

你是“监管科技 + 数据可视化 + 前端架构”专家。请基于已有系统（Next.js + Tailwind + ECharts + ModelA接口）设计并输出一套可直接工程落地的增强方案。

## 已有接口（必须复用）
- `GET /api/modela/v2/view`
- `POST /api/modela/v2/modea_report`
- `POST /api/modela/v2/integrated_closed_loop`

## 业务闭环（必须完整体现）
1. 风险预测（节点/边 7类风险概率）
2. 智能抽检（风险收益-成本双目标）
3. 反馈回写（阳性/阴性）
4. 传播模拟（12h 预测 vs 真实）

## 目标
让非技术老师在 3 分钟内看懂：
- 系统在做什么
- 依据是什么
- 结果能否支持决策

## 你必须交付
### A. 信息架构（四层）
- L1 总览层：一句话结论 + 4~6 个关键KPI
- L2 机制层：四步闭环流程图 + 状态
- L3 证据层：节点解释（贡献拆解、规则命中、传播来源）
- L4 执行层：抽检计划、复检建议、报告导出

### B. 可视化清单（逐图说明）
每个图必须给出：目标、输入字段、视觉编码、交互动作。
至少包含：
- 异构主图（节点/边风险同屏）
- 反馈前后增益图（Precision/Recall）
- 12h 传播对照图
- 抽检策略执行表

### C. “轻3D”增强（务实可落地）
请不要提出高风险、难维护的炫技方案。优先“2.5D可读性增强”：
- 风险高程柱（risk as height）
- 镜头聚焦（点击节点后自动定位）
- 节点爆炸视图（7类风险条 + 邻域贡献）
并给出：
- 最小可行版本（1~2天可完成）
- 完整版（1周可完成）

### D. 代码级交付
输出可运行代码骨架：
- `ModelAV2Workspace`
- `GlobalSituationBoard`
- `WorkflowPipeline`
- `NodeEvidencePanel`
- `ActionExportPanel`
并给出状态管理与数据流（React Query / Context）建议。

### E. 性能与稳定性
必须给出硬约束策略：
- 1k+ 节点时如何保持流畅
- 如何降级（边过滤、标签按需显示、分层渲染）
- 如何避免编译/运行错误（依赖版本、类型约束）

## 输出风格要求
- 必须“可执行”，不能泛泛描述
- 按“先结论、后方案、再代码”结构输出
- 每一项都有优先级（P0/P1/P2）和工时估计
